## 工具 1：`sales_sql_query`（SQL 查询工具）

| 项 | 设计 |
|---|---|
| 目的 | Agent 直接对 ecommerce_db 跑分析 SQL（你 sql_analysis.sql 的 5 段就是起点） |
| 参数 | `sql: str`（必填）、`row_limit: int = 50` |
| 输出 | 查询结果转 markdown 表格字符串（模型读表格比读 JSON 省 token） |
| 你亲手写的核心 | pymysql 连接 + 查询执行 + 结果格式化 |
| 错误处理清单 | ① **只读守卫：拒绝非 SELECT 开头的语句**（安全+面试考点）② 连接失败给可读错误 ③ 空结果提示 ④ row_limit 防止大结果撑爆上下文 |
| 依赖 | `uv pip install pymysql`；MySQL 里导入三张表（你 README 里写过流程） |
| 面试考点 | 为什么限制只读？为什么限制行数？（上下文窗口和 token 成本——呼应考核题 3） |

## 工具 2：`sales_stats`（pandas 统计工具）

| 项 | 设计 |
|---|---|
| 目的 | 不写 SQL 也能出统计口径，数据走 CSV（ your extracted_code.py 74-181 行的逻辑函数化） |
| 参数 | `analysis_type: enum["monthly", "category", "user", "top_products", "repurchase"]`、`top_n: int = 10` |
| 输出 | JSON 表（列名中文，模型可直接引用） |
| 你亲手写的核心 | 5 个分析函数（把你 notebook 里的 groupby/agg/merge 拆成独立函数） |
| 错误处理清单 | ① analysis_type 不在枚举内报错并回显合法值 ② CSV 文件缺失 ③ 日期列解析失败 |
| 设计要点 | **枚举参数 > 自由文本参数**：枚举让模型几乎没有传错参的空间（呼应考核题 6 的 temperature 讨论） |
| 面试考点 | 为什么同时留 SQL 工具和 pandas 工具？（SQL=取数口径灵活；pandas=复杂逻辑好写——Agent 按问题选，这正是工具设计给模型留决策空间） |

## 工具 3：`plot_chart`（Plotly 绘图工具）

| 项 | 设计 |
|---|---|
| 目的 | 把前两个工具的统计结果画成交互图，输出 HTML 文件（你 notebook 87-170 行的 px 用法） |
| 参数 | `data_json: str`、`chart_type: enum["line","bar","barh","histogram","pie"]`、`title: str`、`x: str`、`y: str` |
| 输出 | 保存 `workspace/charts/时间戳_标题.html`，返回文件路径 + 一句图表解读提示 |
| 你亲手写的核心 | chart_type 分发到对应 `px.*`，落盘 `fig.write_html()` |
| 错误处理清单 | ① data_json 解析失败 ② x/y 列不存在于数据 ③ chart_type 非法 ④ 目录自动创建 |
| 面试考点 | 为什么返回路径而不是让模型复述数据？（防止模型转录数字时编造——图表是真数据，文本才需要防幻觉） |
